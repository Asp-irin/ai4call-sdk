# Voxgig SDKgen — Developer Experience Report

## API Selected

I selected the **AI4CALL API**, an AI voice-agent SaaS platform. It provides a downloadable OpenAPI 3.0.3 specification and does not have an official SDK, making it a useful candidate for evaluating SDK generation.

## Testing Approach

I generated the Go SDK and created a small `playground` to compare three read-only approaches for listing assistants:

1. Direct `net/http` request
2. Generated SDK's semantic `Assistant.Load` call
3. Generated SDK's lower-level `Direct` method

Credentials are read from environment variables, and no resources are modified.

Both the raw HTTP request and `Direct` call use:

```text
GET /api/v1/assistants
```

and return a successful response.

## Observations

### 1. Generated SDK route-selection issue

The OpenAPI specification defines separate operations:

```text
GET /api/v1/assistants              → listAssistants
GET /api/v1/assistants/{assistantId} → getAssistant
```

However, both routes are mapped under `Assistant.Load`, while `Assistant.List` remains unsupported.

Calling:

```go
client.Assistant(nil).Load(nil, nil)
```

does not provide an ID or documented pagination field. The generated route selector therefore falls back to `ownPoint`, which prefers a route containing a path parameter. As a result, the SDK sends:

```text
GET /api/v1/assistants/{id}
```

The API interprets `{id}` literally and returns `400 INVALID_ASSISTANT_API_KEY`.

The `Direct` method correctly calls `/api/v1/assistants` and returns `200`, confirming that authentication and the OpenAPI endpoint are correct. The issue is therefore in the generated SDK's route mapping/fallback behavior, not the playground.

Importantly, `limit` is **not required by the API**; it only appears as a generated route-selection field.

### 2. Documentation and Onboarding

The GitHub `tutorial.md` was useful, but onboarding requires navigating concepts such as targets, target groups, API definitions, and the operation pipeline.

A simpler workflow could be:

```text
API → Create Project → Import Spec → Select Targets → Generate → Test
```

The generated SDK documentation explains standard operations such as `load`, `list`, `create`, `update`, and `remove`, but could better explain unsupported operation stubs and how to diagnose mismatches between OpenAPI operations and generated methods.

### 3. Use of AI

I used codex for generating the code for playground scripts inorder to verify the generated sdk's by calling them inside it but the code which is generated by AI assistant was reviewed thoroughly by myself.
